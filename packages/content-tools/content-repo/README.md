# 内容仓

这里只保存技术文章、说说、「关于我」和文章号码计数器。创建与发布使用锁定的轻量工具，不需要网站源码、Astro 或本地网站构建。

这里是唯一写作入口。内容仓 `main` 推送和源码仓 `main` 更新都由本仓的统一流程发布。

需要 Node.js >=24.11.0，本机已安装并登录 GitHub CLI。

## 首次安装

```sh
git clone git@github.com:jasper0507/blog-content.git
cd blog-content
npm ci
```

依赖由 lockfile 锁定到固定发行包，不提交 `node_modules/`。

## 创建

```sh
npm run new:post -- "文章标题"
npm run new:shuoshuo
```

创建只写本地文件，不访问 Git 或网络。文章按标题生成文件并分配稳定 ID；说说按上海时间生成稳定 ID。同名不覆盖，失败不占号。

模板默认 `draft: false`。补齐文章摘要和正文，或说说正文后再发布。暂不公开时改为 `draft: true`；草稿会随提交保存到本仓，但不会进入公开网站。发布命令不会修改 `draft`。

## 发布

```sh
npm run publish
npm run publish -- "发布 Go 并发笔记"
```

不填说明时使用「更新博客内容」，不追问。命令先展示并提交写作内容（`posts/`、`shuoshuo/`、`about.md`、`post-next-id.json`）的新增、修改和删除，不夹带入口、配置或工作流。

推送成功不等于上线。只有远端校验、构建和部署都成功才会报告已上线；校验或构建失败时内容已保存但未上线，网站保留上一次成功版本。推送失败时远端没有该提交，不报告已保存。

## 失败重试

修复后再次运行 `npm run publish`。没有新的写作改动时不会制造空提交，而是重新触发发布并等待结果。推送失败或远端超前时保留本地提交，不强推、不自动撤销。

## 工具升级

普通网站更新不要求更新本地工具。工具本身需要升级时，由开发者更新本仓依赖和 lockfile；创作者再运行一次 `npm ci`。不要手改发行包版本。

## 内容格式

### 发布技术文章

在内容仓运行命令创建技术文章；只提供标题（有空格时加引号）。公开网址由系统分配数字稳定 ID，不必也不允许指定号码：

```sh
npm run new:post -- "深度学习笔记"
```

命令会把标题写入模板，按标题生成 `posts/深度学习笔记.md`（去掉文件系统非法字符），并分配 `/posts/1/` 这类网址。同名文件不会被覆盖；创建失败时不会占用号码。改标题不会改文件名或网址。

```md
---
title: "深度学习笔记"
description: "用于列表、搜索与页面元信息的简短摘要。"
publishedAt: "2026-08-11T10:00:00+08:00"
tags:
  - "Astro"
  - "前端开发"
draft: true
# 禁止修改
id: 1
---

从这里开始写正文。
```

- 模板自动填写标题、当前上海时间、`tags: []`、`draft: false` 和系统分配的 `id`；摘要与正文留空，补完前构建会失败。
- `title`、`description`、`publishedAt`、`draft`、`id` 必填；文章不维护更新时间，`updatedAt` 和其他未知字段会使构建失败。
- `id` 是正整数稳定身份，由创建命令写入；模板在该字段上方注明「禁止修改」。计数器文件 `post-next-id.json` 也不要手改。
- `tags` 可省略或留空，同一篇文章内标签不得重复，也不需要预先登记。不同标签若生成相同网址，构建会失败（草稿也参与检查）。
- `publishedAt` 必须是加引号的有效上海时间字符串 `"YYYY-MM-DDTHH:mm:ss+08:00"`；未加引号的 YAML 日期值、UTC `Z` 和其他时区均无效。
- `draft: true` 不进入公开页面；准备发布时改为 `false`。发布时间只用于显示和排序，不提供定时发布。数字网址也不是发布时间顺序。
- 正文不能为空。文章图片使用外部图床，并以普通 Markdown 图片语法引用。
- 正文可用 GFM（表格、任务列表、删除线、自动链接、脚注）、`==高亮==`、`$...$` / `$$...$$` 公式和原生 `<details>`。代码块支持 `title="file.js"`、行高亮与 diff 标记。代码与行内代码中的 `==` 保持原样。
- 准备公开时确认 `draft: false`，再运行 `npm run publish`。

### 发布说说

运行命令创建带上海时间稳定 ID 的说说：

```sh
npm run new:shuoshuo
```

命令会生成 `shuoshuo/YYYYMMDD-HHmmss.md`。文件名形成 `/shuoshuo/YYYYMMDD-HHmmss/` 独立详情页网址，创建后不要重命名。编辑生成的文件：

```md
---
publishedAt: "2026-08-14T12:00:00+08:00"
draft: false
---

今天完成了博客的日常发布流程。
```

- 说说没有作者标题；时间流保留摘要折叠，独立详情页始终显示完整 Markdown。
- 可以只有文字、只有 Markdown 图片，或两者都有。摘要从 Markdown AST 的普通文本和图片节点自动投影，最多 80 个用户感知字符；图片用 `[1 Image]`、`[N Images]` 计数并默认在折叠状态隐藏。
- 代码、公式和原生 HTML 不单独参与摘要投影；只有这些节点、且没有普通文本或图片的说说会使构建失败。
- 说说只允许 `publishedAt` 和 `draft` 两个字段；标题、摘要、标签等额外字段会使构建失败。
- `publishedAt` 和文件名由命令按当前上海时间生成；可修改发布时间，但不要修改稳定 ID。发布时间格式要求与技术文章相同。同一秒内重复创建会因文件已存在而失败，下一秒重试即可。
- 想暂不公开时改为 `draft: true`；准备公开时恢复为 `false`，再运行 `npm run publish`。
- RSS 收录说说摘要，不含完整正文；说说不进入站内搜索、标签或归档。

### 关于我与图片

编辑根目录 `about.md`，可以留空但不能删除。正文图片继续引用现有图床。博客设置、首页主视觉与字体由开发者在源码仓维护。
