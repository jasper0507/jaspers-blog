# 限定 Markdown 写作能力

技术文章与说说使用普通 Markdown，不要求作者编写组件代码。默认支持 KaTeX 数学公式、GFM 表格/任务列表/删除线/自动链接、Shiki 代码高亮及文件名/行高亮/diff 标记、标题锚点、自动文章目录和原生 `<details>` 折叠内容。Shiki 继续负责语法识别和上述附加能力，但亮暗两套 token 颜色映射到 Kraft Paper 色板，使代码块背景、边框与语法颜色形成同一视觉系统。

Kraft Paper 未定义 `<details>`，网站按其视觉语言使用同色系细边框，不表现为厚重卡片。

2026-08-24 修订：真实内容尚未使用 GitHub Alert，当前不支持也不验收 `[!NOTE]` 等专用语法；删除对应 AST 转换、图标和样式。真实技术文章需要该语法时，再加入满足当时内容的最小实现。本修订取代此前的提示块范围及 ADR-0021 对提示块回归的要求。

第一版不引入 Mermaid 或 MDX：当前内容不依赖它们，Mermaid 会增加浏览器端脚本，MDX 会让内容与组件代码耦合；出现实际内容需求时再单独加入。
