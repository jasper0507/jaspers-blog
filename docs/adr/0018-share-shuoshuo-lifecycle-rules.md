# 说说创作与发布共享领域规则

说说创建与网站发布是前后两个不同用例，不把创建命令和 Astro collection 描述成可互换的 adapter。两者共享稳定 ID、上海时间、frontmatter 和 permalink 规则，避免同一不变量由创作与发布路径分别维护，同时保留各自独立的执行入口。创建命令以当前上海时间预填发布时间；作者可按需修改，网站只读取而不自动改写内容，稳定 ID 也不随之变化。

发布侧只暴露一个已公开说说快照，集中负责 intake 后的正文校验、草稿过滤、确定排序、日期与摘要投影、可访问标签、permalink 和正文渲染；首页、说说时间流和 RSS 不接触 Astro `CollectionEntry`、`data`、`body` 或 `draft`。创建命令与 Astro collection 保持各自现有入口，只共享纯领域规则，不增加 port、兼容层或 adapter 抽象。

说说不增加作者维护的标题或摘要。发布投影统一生成一行摘要：有文字时使用第一行有效文字；只有照片时按数量显示 `1 Image`、`2 Images` 等占位符。首页和 RSS 使用这条摘要，RSS 不包含完整正文；可访问标签和 permalink 也由同一投影生成，各调用方不再分别拼装这些规则。

创建命令自动写入通常无需修改的 frontmatter：当前上海时间的 `publishedAt` 和默认值为 `false` 的 `draft`；作者确有需要时再修改。说说只允许这两个 frontmatter 字段，标题、摘要、标签等额外字段使构建失败而非被静默忽略。两个字段在文件中仍然必填，默认值只在创建时写入，不由构建过程补齐。

创建命令不替作者填写内容，生成文件的正文初始为空；作者写入真实内容前，构建明确失败，避免默认公开时误发布占位文字。所有说说（包括草稿）都必须具有有效的稳定 ID、发布时间、草稿状态和非空正文；违反规则时构建明确失败，不静默补值或忽略错误。

稳定 ID 继续采用上海时间的 `YYYYMMDD-HHmmss` 格式。若同一秒内重复创建导致 ID 冲突，命令明确失败且不覆盖已有内容；作者下一秒重试，不为这一罕见情况增加随机后缀或第二套 ID 格式。

文件名是稳定 ID 的唯一来源，生成后不得重命名。项目不增加 ID 登记表或在 frontmatter 中复制 ID；构建校验格式与唯一性，但不能识别从一个合法 ID 到另一个合法 ID 的手动重命名，误操作依靠 Git 历史恢复。

创建命令将文件直接写入 `src/content/shuoshuo/`，目录不存在时自动创建；所有说说保持平铺，不按年或月增加子目录。

说说的 ID 生成、发布时间输入和页面日期投影统一使用 `Asia/Shanghai`。frontmatter 中的发布时间必须是加引号、带 `+08:00` 的完整日期时间字符串；未加引号的 YAML 日期值、缺失时区或使用其他时区都使构建失败，避免依赖 YAML 隐式类型、机器环境或发生静默时间偏移。

`draft` 是唯一发布开关：`true` 时从所有公开输出排除，`false` 时随下一次构建立刻公开。发布时间只用于显示和排序，不提供定时发布；需要晚些公开时，作者届时再退出草稿状态并构建。

公开说说按发布时间降序排列；发布时间完全相同时，再按稳定 ID 降序排列，使手动复制时间或批量整理内容后的输出仍然确定。

核心验收只保留一条穿过完整 interface 的生命周期演练：在临时目录运行创建命令，先验证空正文使构建失败，再写入正文并通过 Astro collection 构建，最后验证首页、说说时间流和 RSS 得到一致的 ID、时间与 permalink，首页和 RSS 使用相同摘要，时间流渲染完整正文。现有页面外观与交互冒烟继续承担 UI 验收，不为同一领域规则叠加重复测试。
