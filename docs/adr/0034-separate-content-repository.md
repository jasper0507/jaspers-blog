# 将写作内容迁入独立私有仓库

技术文章和说说的发布提交与项目维护混杂，日常写作需要独立的 Git 工作流。已确认的设计边界是：技术文章、说说、“关于我”正文和技术文章号码计数器迁入独立私有内容仓库；日常创建、编辑、提交和发布均从内容仓库完成，无需向源码仓库提交内容变更。博客设置、首页主视觉照片、字体、页面和构建工具留在源码仓库，正文图片继续使用现有图床。

创作者只维护内容仓库，日常关注 Markdown，使用 `npm run new:post` 等命令创建内容；开发者维护源码仓库并使用正常的 Git 与 PR 流程。创作者无需克隆、关联或同步网站源码副本，仅安装创建与发布所需的小工具。工具实现与内容规则保持单一来源，由源码仓库维护。

内容仓库保留 `posts/`、`shuoshuo/`、`about.md`、`post-next-id.json`，保存写作内容与号码状态；`package.json`、`package-lock.json`、`.github/workflows/publish.yml`、`.gitignore` 和面向创作者的 `README.md` 提供少量命令与发布入口。入口由开发者配置维护，不手工复制源码仓库中的内容规则、渲染逻辑或框架依赖。依赖安装到不纳入 Git 的 `node_modules/`，本地不生成网站构建产物。

源码仓库通过 GitHub Releases 分发只包含创建与发布能力的独立工具包，内容仓库用固定版本的压缩包地址和 lockfile 锁定依赖，首次通过 `npm ci` 安装，不另建 npm 发布账号。网站更新不要求同步升级本地工具；工具本身需要升级时，由开发者更新内容仓库中的依赖版本，创作者重新安装依赖。网站与工具共用源码仓维护的领域规则，工具包不携带页面、Astro 或整站依赖。本机已安装并登录 GitHub CLI，发布工具直接复用现有身份查询私有仓库发布结果和触发重试，不增加 GitHub CLI 安装、登录或自建凭据管理流程。

创作者日常使用 `npm run new:post`、`npm run new:shuoshuo` 和 `npm run publish`，内容仓不提供本地 `dev`、`build` 或完整网站预览，正式校验和构建交给自动发布流程。`publish` 展示待提交变更，自动提交全部写作内容的新增、修改、删除及号码计数器，推送后等待远端校验、构建与部署并报告结果；入口脚本和配置不自动提交。允许提供自定义 Git 提交说明，不提供时由命令生成默认说明。命令不修改 `draft`，草稿随提交保存但不进入公开网站。推送成功不等于发布成功，远端校验失败时报告内容已保存但未上线，网站保留上一次成功版本。

发布失败时保留已提交内容和当前线上版本，修复后再次运行 `publish`；没有新内容改动时也允许重新触发部署，不制造空提交，不自动撤销内容。正式部署采用基本串行控制并记录实际使用的两仓提交，避免旧版本覆盖新版本；并发概率很低，不为中间版本逐一上线或复杂任务调度增加机制。

内容仓库推送主分支、源码仓库合并主分支都触发网站校验与发布，保留 `draft` 作为内容公开开关。新内容仓库从迁移时的当前文件快照开始，不提取旧提交历史，也不改写源码仓库历史。仓库私有不改变已发布页面的公开性，也不会清除原公开仓库中的历史内容。

正式发布统一由私有内容仓库的工作流执行：内容推送直接触发，源码合并由源码仓库通知内容仓库触发。流程取得两仓最新主分支的准确提交并记录，完成校验和构建后通过 Wrangler 上传现有 Cloudflare Pages 项目，关闭该项目原有的自动 Git 部署。公开源码验证使用公开示例内容，真实内容与生产构建日志留在私有发布流程中；跨仓触发凭据与 Cloudflare 部署凭据分别配置在需要它们的仓库，发布自动化由开发者维护。

自定义提交说明使用位置参数：`npm run publish -- "说明"`，`--` 后保留空格。不提供说明时使用“更新博客内容”，不交互追问。日常命令如下：

```sh
npm run new:post -- "文章标题"
npm run new:shuoshuo
npm run publish
npm run publish -- "发布 Go 并发笔记"
```

迁移保留所有技术文章稳定 ID、说说稳定 ID 和文章号码计数器，保持既有公开网址不变。本站仍采用静态 Git 发布，不引入 CMS、数据库或管理后台。

本方案拟取代 ADR-0004 中单仓内容发布、内容直推源码主分支及不引入发布包装和独立内容仓库的决定，以及 ADR-0029 中内容仓库保持公开的决定；源码仓库仍保持公开，其维护变更继续通过 PR，并等待 `verify` 与 `browser-smoke` 成功后合并。本文为访谈收敛后的设计草案，尚未实施仓库迁移、工具分发或部署配置变更。
